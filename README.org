#+TITLE: thock
#+AUTHOR: mwlabs
#+OPTIONS: toc:2 num:nil

A web page for recording mechanical keyswitches into a microphone and
listening back. Press a switch, thock saves each press as a clip,
averages the spectrum across many presses into a per-switch
fingerprint, and plays a library of switches back as if you were
typing prose. Useful if you're curious what a switch sounds like
before buying it.

Static site, runs in the browser, files stay local.

Live: *https://thock.mwlabs.be*

* What's in the UI

** library

A small set of pre-recorded switches you can import with a click. The
current set is the 16 switches in the Kailh Choc v2 tester pack from
keebart. Importing copies the files into your browser's local
storage; you can remove them whenever.

** record samples

Click /+ create a switch/, then /▶ record samples/. A visual
metronome paces you through ~60 taps that gradually speed up. After
the run, thock picks ~30 of the cleanest taps across the tempo range
and keeps those. If too few were usable, it asks before saving.

** fingerprint

Averaged smoothed spectrum across all the samples of the currently
selected switch. Selecting a different switch redraws the curve on
the same axes for direct comparison.

** typist

Plays back the selected switch's samples as paragraphs of prose at a
given WPM. Source defaults to a small set of bundled passages;
attempts to fetch live articles from libertis.net at boot, falls
back if blocked.

** export

For switches you recorded yourself, /export/ on the samples row
downloads a zip containing the WAVs plus a =meta.json= built from
the name / family / type / weight you typed in. Email the zip to
*info@mwlabs.be* to contribute it to the library.

* Running locally

Static site, no build step:

#+BEGIN_SRC sh
python -m http.server 8765
#+END_SRC

Or with [[https://devenv.sh][devenv]]:

#+BEGIN_SRC sh
devenv up
#+END_SRC

* What's in this repo

- The thock web app (=index.html=, =app.js=, =styles.css=,
  =capture-worklet.js=)
- =scripts/bundle_library.py= — converts a folder of WAV recordings
  into the FLAC catalog the site serves

The curated library payload lives in a separate private repo mounted
at =library/= as a git submodule. Reasons for the split:

- *Repo size.* Code is small text; the library is binary blobs that
  will grow. Keeping them apart means the code repo stays
  clone-in-seconds, CI fast, and GitHub's web UI happy.
- *License boundary.* Code is MIT. Library recordings aren't (we
  don't want them re-released under MIT). Two repos, two LICENSE
  files, clear line.
- *Git fit.* Git is good at line-diffs and bad at binary churn —
  separating them lets both repos use git the way it's actually good.

What the split does *not* do: stop someone from downloading the
library. The files are served on the public web; two lines of
=curl + jq= and you have the whole thing. The submodule hides
filenames from GitHub source browsing, not from runtime scraping.

If you clone and have access to the library repo:

#+BEGIN_SRC sh
git submodule update --init
#+END_SRC

Without access, the /library/ button stays empty; recording your
own switches still works.
